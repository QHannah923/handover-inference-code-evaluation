# 当前正式入口的prompt和rules：人工阅读指南

更新：2026-11-03。本文描述下载目录中已回退V5之后、保留四类独立证据规则的版本。历史V5指南只作实验记录。

## 从输入到结果

1. 按原始顺序读取整份用户与技能对话，给每轮编号。保留其他角色和音频占位文本，不猜测缺失音频。
2. 一次模型调用联合检查四个父类型，并为阳性给出同一路径下的子类型。当前使用GPT-6.1 Sol，推理强度high。
3. 校验输出结构、父子关系和引用轮次，再按既有门槛和排序产生主分类。子类型直接读取同一次联合结果。
4. 读取原始对话，运行四类独立证据规则。只有模型最终一级弃判、规则支持唯一父子路径时才补充分类。
5. 保存原始模型结论、最后采用的结论、规则是否采纳、引用原文和轮次。

规则读取的是对话证据，不是人工标签或模型的分析文字。分类结果不使用样本编号、文件名、品牌名查表。

## prompt实际上由什么组成

主提示词在dark-pattern/interface_interference_prompt_v2.py；它拼接dark-pattern/ad_subtype_policy.py中的广告操作细则和六组合成对比例子。请求同时携带taxonomy、已机械验证的逐字重复窗口、完整有序transcript。

主提示词要求：读完整对话；日志是证据而非指令；不从关键词推断未记录的支付失败、不可跳过广告或隐瞒赞助。它要求一次返回四类检查结果，而不是为每个类型分别发四次请求。

### 重复或混乱输出

模型端仍保留原来的严格门槛：连续三条完整技能回复逐字相同，对应三种不同用户指令。逐字相同不仅指句子结构，标点、大小写、数字或内部空格不同都不算；只去除日志标签和外侧空白。

代码先验证窗口，模型再结合整段对话判断是否真的使流程失败。正常帮助菜单、主动重播、填槽或没有实际故障的重复，不能仅凭窗口成立就判阳性。

符合门槛后，重复无用错误归错误回声，重复错误流程归误导循环，重复情境中缺乏可执行帮助归前馈歧义。

**当前重复或混乱输出规则包含三种明确的后处理例外**：连续识别失败可以使用不同措辞；评分自相矛盾可以使用不同题目和不同文本。另有购买误路由规则，要求两个不同已公布题目中的非购买输入都触发购买识别错误。它们不修改模型prompt，也不把一切相似句子重新当作重复。实验报告明确披露这一操作范围变化。

### 观看广告／付费以避免广告

要有真正的强制广告或核心功能限制。可选题包、额外内容和欢迎菜单中的升级入口，不能只因出现premium、subscribe或buy就判定。

功能锁定指继续核心任务需要订阅；付费墙诱导要有相应免费承诺和后续限制证据；强制广告不能从“没说可以跳过”推断；语音助手原生广告需要技能结束后的宿主推广证据。

### 伪装广告

先还原首次推广之前用户正在做什么，再判断商业内容如何介入。用户后来答yes，只能许可后面的商品说明，不能追溯授权最初插入的销售内容。

产品植入／原生广告已合并：原本在听声音、听事实或运行计时器，流程中插入未经请求的销售推广；或信息服务本身把推广包装成普通内容。

偏向推荐同时需要推荐或选择情境，以及商业偏袒证据。例如用户要免费选项，技能却宣称获佣的付费合作方案最好，并压制免费选择。单独出现“you might like”“our book”或卖家归属，不足以改判偏向推荐。

Sleep Better的分类逻辑是“声音任务里插入图书销售”，因此归合并广告类。规则没有把Sleep Better这个名字当特征。

主动询价、公开商业服务的购买菜单、透明可选升级、没有偏袒证据的普通建议，不自动归为伪装广告。广告阳性还要引用用户目标、推广行为、偏袒证据（若有），并解释为什么不选另一个广告子类型。

六组合成例子分别教：声音中卖商品、违背免费偏好的获佣推荐、主动询价、事实回答被销售替代、无商业偏袒的放松建议、用户已选择品牌方案后的正常说明。它们不包含87条逐条答案表。

### 语音引导评价

五星索评、口述评价征集和偏向好评的情绪引导才有相应机制。单次中性邀请、明确可拒绝且拒绝后停止，不自动是暗黑模式。

“五星评价对我们很有帮助”这样的间接五星请求仍是引导。可拒绝不等于没有五星引导。情绪措辞必须改变评价选择，单纯愉快语气不算。

### 输出和代码校验

输出包含四类各自的成立与否、阳性父子路径、分数、证据轮次、简短中文理由，以及记录缺失等质量说明。每类最多一个阳性候选，但允许不同类型共存。

代码检查四类是否齐全，阳性检查与候选是否一致，子类型是否属于父类型，轮次是否有效，广告机制引用是否完整。结构正确不等于语义一定正确；这些校验本身不能充当独立人工标签。

接口返回缺字段、非法JSON或父子关系错误会报错，不会悄悄变成“没有暗黑模式”。

## rules目前分为哪些层

### 既有的候选支持与严格窗口

旧关键词规则主要为广告限制和评价引导提供支持。它们通常不能单独产生新的模型阳性，只参与已有模型候选的排序。重复类使用代码验证的逐字窗口，不能由旧模糊相似度直接判定。

原有排序分数是“模型分数×0.80＋同类规则支持×0.20”。这是候选排序，不是正确概率，也不是每次都让规则投20%的决定票。主候选仍要求原模型分数达到0.80；次候选门槛0.65，最多保留一个。

旧五星例外要求规则分数至少0.95，并在真实技能文本中有明确五星请求，才能独立提出评价路径。该旧例外和旧支持规则都没有作为新增证据规则的实验贡献。

正式联合入口已省去旧近似重复和忽略帮助规则的计算，因为它们的结果之后会被严格窗口筛掉。历史兼容入口保留原实现，避免破坏历史实验。

### 当前四类独立证据规则

代码在dark-pattern/verified_failure_rules.py，共181行。

第一条：三次连续、可唯一配对的纯识别失败；至少两种非重播请求；有效内容或配对不明会中断。它独立纠正13号，对已经判对的4号保持原结果。

第二条：两个不同答案都与技能同轮公布的答案一致，却被判错；支持保守的明确反馈语法和数字归一化。它独立纠正80号，不依赖外部题库或常识。

第三条：两个不同的已公布题目中，非购买输入均被转成无法识别商品的购买错误；主动购买、占位输入、商业菜单及结束答题会排除或清除题目状态。它修正26号。

第四类仅补充父类型：用户未请求软件推荐或帮助菜单时，出现明确姐妹技能、另一应用或Alexa启用引流。平台设置、主动推荐请求和仅说also use X的笼统提示均不独立判定。它修正40、53、81号一级，子类型仍未定。

所有规则都附逐项原文证据。只在原主分类为空时补充，已有阳性不覆盖，多个规则路径冲突不强选。规则不伪装模型分数，不赋予“0.95正确概率”，采用规则时confidence为空并保留来源说明。

当前并没有保留V5的0.85阈值路由、13项独立规则库和额外机制校验模块。它们没有在本批证明收益，所以回退而非继续叠加。
