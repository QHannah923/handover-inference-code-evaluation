# Project Handover

## 1. Research story

This project studies dark patterns in voice-user-interface interactions, using Amazon Alexa Skills as the current empirical setting. It builds on dialogue traces generated by the upstream VITAS exploration system.

The intended research pipeline is:

```text
VITAS
  ↓
Alexa Skill dialogue traces
  ↓
5,924 logs
  ↓
full VUI dark-pattern taxonomy
  ↓
rule / structural / optional LLM detection
  ↓
multi-label taxonomy-path predictions
  ↓
supporting dialogue evidence
```

The pipeline above is the intended full research pipeline, not a statement that every stage has been implemented and validated. The only implementation represented by the repository's sole Git commit is the Interface Interference type/subtype classifier. A later full-taxonomy prototype exists in the working tree, but its provenance and validation status are **`待核实`**. Neither implementation currently uses the VITAS FSM/state representation as an input feature.

### Current stage

## 2. Frozen research scope

> **Scope is frozen; taxonomy definitions are not.**

The paper studies the full VUI dark-pattern space represented by the three current top-level categories:

1. `OBSTRUCTION`
2. `SNEAKING`
3. `INTERFACE INTERFERENCE`

The current working taxonomy contains 12 types and 37 subtypes. Interface Interference is one branch of the full paper scope and must not be presented as the sole scope.

The current 3/12/37 structure is the post-verification working taxonomy. Individual definitions or paths may still be merged, refined, renamed, or removed when supported by annotation or observability evidence. The project should not restart broad taxonomy construction from scratch.

## 3. Project history

### 3.1 VITAS upstream work

The `vitas experiment/` directory contains an earlier automated Alexa Skill exploration project. VITAS models Skill behaviour using state-like representations, generates or selects user inputs, explores dialogue flows, and records Skill responses. The directory includes state mappings, large-scale logs, comparative systems, and ablation artifacts.

VITAS is the source context for the current dialogue traces, but its code and FSM representation are not integrated into the committed Interface Interference classifier. Integration with the later full-taxonomy candidate is also not established.

### 3.2 Dialogue-log dataset

The current project contains 5,924 tagged text logs in:

```text
dark-pattern/5924dataset(waiting for labelled)/
```

Each non-empty line is normally tagged as `[USER_INPUT]` or `[SKILL_OUTPUT]`. The current parser converts these lines into ordered `USER` and `SKILL` turns.

### 3.3 Initial weak-label analysis

`dark-pattern/5924first-layer-label.csv` assigns a top-level category and natural-language reasoning to each of the 5,924 logs. The available artifact has the following label distribution:

| Weak label | Count |
|---|---:|
| `No` | 3,538 |
| `OBSTRUCTION` | 2,299 |
| `INTERFACE_INTERFERENCE` | 87 |

These labels appear to be model-assisted weak labels. They must not be described as human gold labels. The artifact does not contain `SNEAKING` as a top-level weak label even though Sneaking is part of the current taxonomy.

The 87 `INTERFACE_INTERFERENCE` entries are the working verification set for this week, not gold labels by themselves. Each item must be checked against the available human ground truth before it is used for accuracy or error analysis.

### 3.4 Committed Interface Interference implementation

The first dedicated detector focused on four Interface Interference types:

- Watch Ads/Pay to Avoid Ads;
- Disguised Ad;
- Voice-Guided Rating;
- Repeated/Confused Output.

It implemented type prediction followed by subtype routing and used rule-first, LLM-fallback logic. The repository's only commit is `d93962c` (`Initial commit: interface interference classifier`), which contains this implementation, its runner, and the 10-case Interface Interference benchmark material.

This is therefore the only source-controlled historical implementation baseline. It is **not yet a validated effectiveness baseline**: the existing smoke benchmark contains only 10 labelled cases, some labels are explicitly tentative, and the runner prints predictions without calculating benchmark metrics. This week's main task is to run the unchanged path on the 87-log verification set and audit its outputs against human ground truth.

### 3.5 Untracked full-taxonomy candidate

The later `taxonomy_classifier.py` attempts detection across all three top-level categories and emits complete category/type/subtype paths. Code inspection shows lexical rules, structural dialogue detectors, optional LLM adjudication, multiple retained predictions, and evidence spans.

However, `taxonomy_classifier.py`, its runner, evaluator, and both 100-log benchmark files are untracked in the current working tree and are absent from the sole historical commit. Who created or modified them, how they relate to the committed Interface Interference work, and what validation they received are **`待核实`**. They must currently be treated as candidate artifacts, not as the completed or canonical classifier.

- The raw VITAS-derived dialogue traces, subject to normal empty-log, truncation, duplication, and platform-attribution checks.
- The current taxonomy definitions as the working result of the existing verification round.
- The existence and content of the committed Interface Interference implementation at Git commit `d93962c`.
- The existing Interface Interference examples as a smoke/reference set for the 87-log code/label audit.
- Human ground-truth labels for the designated 87-log verification set, once their source and annotation status are recorded in the report.

### 5.2 Preliminary and not yet sufficient for paper claims

- The 5,924 top-level weak labels.
- The two 100-sample benchmark sets as final held-out evaluation data.
- Results from the optional LLM path without an explicit run manifest.
- Primary-label accuracy as the main measure of a multi-label task.
- Rule `confidence` values interpreted as probabilities.
- Any result for which code commit, data version, prompt version, model version, or actual LLM invocation is unknown.
- Claims that the formal FSM improves detection; that integration has not been implemented or evaluated.
- Claims that the full-taxonomy implementation was completed or validated as part of the committed historical project.
- Full-taxonomy working-tree runs until the origin and role of the untracked implementation are established.

### 6.2 Candidate full-taxonomy path

The untracked working tree also contains:

```text
run_taxonomy_classifier.py
  → taxonomy_classifier.classify_file
  → parse dialogue turns
  → lexical taxonomy rules
  → structural dialogue detectors
  → optional non-interface LLM adjudication
  → optional Interface Interference path
  → deduplicate full taxonomy paths
  → ranked output with evidence
```

The candidate predicts complete category/type/subtype paths directly. Although the paper describes category, type, and subtype as hierarchical levels, this implementation is not a strict three-stage router across the full taxonomy. It must not become the canonical experimental path until its provenance, relationship to the committed code, and validation status are documented.

### 6.3 Rule detection in the candidate

Rules associate patterns with a full taxonomy path. They typically inspect Skill turns, user turns, or both. Examples include launch/access failures, account linking, auto-renewal language, personal-data requests, advertising language, rating prompts, and generic error messages.

The attached score is a manually assigned ranking score. It is not trained or calibrated.

### 6.4 Structural detection in the candidate

The candidate implementation contains dedicated logic for behaviours that cannot be represented well by isolated keywords, including:

- stop/exit attempts followed by continued interaction;
- farewell followed by later Skill output;
- logs ending after substantive user input;
- requested versus started Skill-name mismatch;
- repeated or near-repeated Skill responses;
- repeated fixed suffix/menu prompts;
- ignored help/repeat/meta requests;
- Skill responses echoing user utterances;
- pause/resume requests replaying prior content;
- derived no-justification privacy predictions.

### 6.5 Optional LLM use

The candidate full-taxonomy classifier can request LLM adjudication for ambiguous non-interface candidates. It can also call the committed Interface Interference type/subtype classifier when interface signals are present.

Current experimental limitation: OpenAI failures are caught and can produce an empty LLM contribution without a run-level failure signal. Formal hybrid experiments must first make requested, attempted, succeeded, failed, and model-version status explicit.

### 6.6 Evidence output

Each prediction can include:

- exact hit turn IDs;
- a padded contextual span;
- copied evidence turns;
- a short reason;
- the detection method.

This evidence is a core research output and should be preserved per predicted path.

### 6.7 Multi-label output in the candidate

The candidate implementation retains a ranked list and up to three secondary predictions after thresholding. On one diagnostic rule/structural-only run of the untracked working tree, 1,522 of 5,924 logs produced at least one secondary prediction. This observation does not establish historical completion or validity.

The research target is:

```text
gold       = set of taxonomy paths
prediction = set of taxonomy paths
```

The current `primary_prediction` field is mainly a presentation/debugging convenience. It must not be assumed to represent a theoretically privileged label unless a justified primary-label policy is later introduced.

## 8. Known research-critical issues

These issues can change the interpretation or validity of paper results.

1. **Multi-label evaluation is incomplete.** The evaluator currently compares only `primary_prediction` against one gold path.
2. **Gold labels are not yet normalized as sets.** The benchmark CSVs contain category/type/subtype columns and an optional `secondary` field, but no canonical taxonomy-path-set representation.
3. **Primary status is not theoretically defined.** Equal-score labels can be ordered by detector execution order.
4. **Scores are not probabilities.** Rule and structural scores are manually assigned and should not be presented as calibrated confidence.
5. **Secondary threshold behaviour in the candidate must be verified.** Predictions are first filtered by the primary threshold, making the lower secondary threshold ineffective in the current candidate implementation.
6. **LLM fallback is silent on failure.** `--use-llm` does not prove that an LLM was invoked or influenced the output.
7. **Experiment provenance is incomplete.** Formal runs require code, data, split, prompt, model, seed, date, failure, and cost records.
8. **Held-out status is unclear.** Both 100-sample benchmarks existed before the latest classifier edits and may have informed development.
9. **Taxonomy observability varies.** Auto-renewal, hidden listening, developer intent, and some platform behaviours may not be identifiable from a dialogue transcript alone.
10. **Failure versus manipulation remains an important boundary.** Skill access errors, unsupported devices, abrupt logs, and dialogue bugs require careful annotation policy.
11. **FSM claims are not implemented.** VITAS state information and the paper's formal model are not used by either the committed Interface Interference path or the candidate detector.
12. **The future canonical path is unresolved.** The committed baseline covers Interface Interference only, while the full-taxonomy candidate is untracked and has unverified provenance.
13. **Interface Interference effectiveness is not yet established.** The 87-log human-ground-truth verification is not complete; the existing 10-case benchmark is only a smoke/reference set, includes tentative labels, and has no automatic scoring path.
